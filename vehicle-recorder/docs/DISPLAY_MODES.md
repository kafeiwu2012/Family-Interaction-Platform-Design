# 横竖屏、全屏与折叠菜单 · 1.2.1

## 使用方式

1. 初始默认为横屏。右上角保留带青绿色边框的 `☰ 菜单` 按钮，点击展开操作面板。
2. 点击“切换为竖屏”或“切换为横屏”，同时改变显示方向和后续片段的播放方向。选择会记住；设备晃动不自动旋转。
3. 再次点击右上角“收起”、按一次返回，或 8 秒无触摸操作后收起面板。录制继续，小型 REC/计时状态和菜单标记保留。
4. 默认预览铺满屏幕；比例不一致会居中裁切预览。点击“显示完整画面”可保留整个画幅，但可能出现黑边；再次点击“预览铺满屏幕”恢复。此开关不切段，不改变保存的视频内容。
5. 设置、录像库、镜头切换、保护及开始/停止均在面板内。面板在横屏和竖屏中采用可滚动布局。

本版按用户最后确认采用手动切换，未启用重力感应自动转向；默认值为横屏，后续记住用户选择。

## 全屏的范围

主界面使用 Window FLAG_FULLSCREEN、布局延伸及 IMMERSIVE_STICKY 隐藏系统状态栏/软件导航栏，并在重新获得焦点和配置变化时恢复。视频 TextureView 占整个应用窗口，控制面板叠加显示，不挤占视频布局。

Android 允许用户从边缘滑动暂时显示系统栏；不能遮盖实体按键、手机边框、系统授权弹窗或系统强制显示的界面。铺满显示可能裁切预览边缘；保存的文件仍是摄像头完整编码画幅。

## 录像方向实现

Android Camera API 1 的传感器安装角度不一定相同，因此读取 CameraInfo.orientation，并结合实际 Display.getRotation 和手动校正角计算：

- 后置：`(传感器角度 - 显示旋转角度 + 校正) mod 360`。
- 前置：`(传感器角度 + 显示旋转角度 + 校正) mod 360`。

Surface rotation 0/1/2/3 对应 0/90/180/270°。录像方向角用于 MediaRecorder.setOrientationHint。后置预览可使用相同角度；前置预览先对不含校正的角取反（mod 360）做镜像方向补偿，再叠加安装校正。前置不额外增加像素镜像操作，保留相机纹理本身的变换。1.2.0 曾错误地复用录像角度，导致常见前置传感器在竖屏时预览倒置；1.2.1 已将预览与录像方向分别计算。

竖屏录像采用 MP4 方向元数据，例如底层编码帧 1280×720，加 90°/270° 后播放器显示为 720×1280。这是方向适配，不是把画面拉伸；外部播放器须支持 MP4 旋转信息。特殊固件若显示倒置，可在“录像画质 → 方向校正”叠加 0/90/180/270°；建议升级后先使用 0° 验证。

## 安全切段

MediaRecorder 不支持在正在录制的片段中修改方向。手动切换显示方向后，服务合并 500 ms 内连续变化；片段不足 1.5 秒时稍后再切，减少极短片段保存失败。然后按顺序保存旧片段、释放旧相机/编码器、重建新方向录制。预览可能在这段时间短暂旋转或停顿，不保证无缝录像。

不会因为切换界面布局而重复触发启动自动录像，也不会因为返回主界面、收起面板或切换铺满/完整预览而主动切段。切段期间继续持有唤醒锁；受保护旧片段仍保留锁定状态，新片段遵循原有保护逻辑。

## 代码入口

| 文件 | 修改 |
|---|---|
| MainActivity | 手动选择横/竖、响应配置变化、全屏 TextureView、52dp 菜单标记、8 秒触摸闲置收起、可滚动面板 |
| Ui | Window 全屏标记与沉浸式布局 |
| RecorderService | 显示角度变化合并、安全方向切段、摄像头安装角度读取及方向元数据 |
| OrientationMath | 可独立测试的前后摄像头方向与 fit/fill 几何计算 |
| OffscreenPreview | 按方向和裁切模式更新投影矩阵，保持图像比例 |
| ClipsActivity | 跟随用户选择的界面横/竖屏模式 |
| AndroidManifest | 主界面处理 orientation/screenSize/keyboardHidden 变化，不因方向切换重新创建 Activity |

旧的 rotation 设置现在是叠加在模式计算结果上的安装校正，不应当作横竖屏切换按钮使用。layout_mode 和 preview_fill 只用于界面与显示策略，不额外占用存储配额。

## 验证

自动化：前后摄像头不同安装角、横屏/竖屏/反向角度、校正叠加、Surface rotation 转换、宽屏裁切、竖屏完整显示和铺满显示的比例均有测试；同时保留配额、命名、锁定与设置策略检查。完整 APK 编译和 lint 由 CI 执行。

R7sm 真机验收待执行：

- 初次安装默认横屏且菜单收起，能看到 REC 和菜单标记；菜单标记无遮挡且点击灵敏。
- 点击展开后所有按钮可访问；横屏小高度面板可滚动；8 秒不操作自动收起，持续触摸不应收起。
- 录制中横→竖→横切换，回放旧/新片段，检查前后摄像头方向、画幅和声音。快速重复切换不应覆盖文件或持续产生空片段。
- 手动停止后切换横/竖、从录像库返回，不应自动重新录像。
- 预览铺满时不拉伸；切至完整画面可看到被预览裁切的边缘，保存文件内容不随预览开关改变。
- 状态栏在正常录制时隐藏；边缘滑动出现系统栏后可恢复沉浸式，系统权限窗口不被遮盖。
- 横/竖两种模式分别熄屏 10 分钟后唤醒，录制仍在，预览与菜单恢复正常。

## 1.2.1 前置竖屏回归

用户提供的 R7sm 照片显示：UI 的 REC 和菜单文字正常，但前置相机画面倒置。该照片只能证明预览异常，不能据此认定保存文件也倒置。因此本次修复只调整前置预览的方向补偿，保留 MP4 方向元数据计算。

典型 270° 前置传感器、显示旋转 0°、校正 0°：录像角仍为 270°，预览角应为 90°。横屏显示旋转 90° 时二者均为 0°，保持原行为。前置安装角为 90° 的情况也覆盖在回归测试中。

验收：方向校正先使用 0°，依次检查前置横屏→竖屏→横屏，再检查后置横/竖屏；分别验证铺满及完整预览。最后回放新保存的前置竖屏片段，确认播放器中的方向。新修复仍待该 R7sm 真机确认，不声称仅凭单元测试完成了硬件验收。
