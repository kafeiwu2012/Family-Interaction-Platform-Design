# 系统范围与模块组织

## 当前范围

家庭影像采集模块的可确认需求为 Android 5.1.1（API 22）手机拍照、无声短录像、串行切换前后摄、本地媒体管理及树莓派照片接收。参考设备是 OPPO R7sm，前后摄均报告 Camera2 LEGACY。已有真机反馈出现并发错误2，因此 v0.4.0 起移除双摄并发执行与诊断入口。

家庭影像采集已提供源码：本机主动启停、常驻通知、定时照片、本地拍照/录像/休息循环、定时交替镜头、5秒单独录像测试、多选删除、ZIP导出、HTTPS照片上传、补传、设备/管理员分离令牌及状态查询。

家庭影像采集尚未提供：视频上传、实时视频、多设备管理、正常任务中的双路并发、推送告警、云对象存储适配器、服务端自动保留期清理。Linux云主机可运行现有接收服务，不等同于已有云存储适配器。

## 行车记录仪模块

`vehicle-recorder/` 是独立的Android应用，包名 `com.family.recorder`，当前版本1.1.0，minSdk21、targetSdk28。已存在代码和独立开发文档：循环分段、配额清理与保护、路径管理、录音、前后摄手动串行切换、GPU预览和录制中设置。没有网络权限，不向家庭采集服务上传视频。不能把它的签名、权限、自动录像策略或安装步骤与家庭采集应用混用。

[开发文档](../vehicle-recorder/docs/DEVELOPMENT.md) 记录架构与自动检查结果；流畅度、熄屏及长时间稳定性仍须真机验收。两个模块尚无已实现的联动接口。

## 后续模块接入

1. 先提供模块需求、运行设备、输入输出、权限、验收标准，再创建与 `android-family-capture/` 并列的独立目录。
2. 每个模块拥有自己的 README、源码、测试和部署文档；在仓库根 README 及本目录索引登记入口。
3. 模块间通信先约定接口、认证、版本及失败重试规则，再实施；避免直接依赖彼此私有数据库或内部文件。
4. CI工作流保留在根 `.github/workflows/`；每个job显式设置所属模块工作目录，产物路径从仓库根计算。
5. 不提交真实令牌、设备照片、数据库、签名私钥或 `.env`。构建缓存与本地配置由模块 `.gitignore` 排除。

“设计家庭物联网系统”历史对话当前没有可读取的需求正文。其设备清单、其他模块、业务联动、网络协议和优先级均待补充；本文件不替代该需求确认。
