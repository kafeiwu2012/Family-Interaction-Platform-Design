# OPPO R7sm / Android 5.1.1 真机测试

以下是待执行步骤，不是已通过结果。记录手机型号、ColorOS/固件版本、API、摄像头报告、APK SHA256、服务器版本以及每项结果。

1. `adb shell getprop ro.build.version.sdk` 应为 22；安装 APK。启动查看摄像头能力，记录 front/back ID 和 hardwareLevel。没有某颗摄像头时应显示拍摄失败，不应自动使用另一颗。
2. 配置 HTTPS/令牌，在手机浏览器验证域名、证书和系统时间；启用定时拍摄。确认常驻通知可见、可打开界面、可停止。检查服务器生成可解码 JPEG，前后摄图像朝向和清晰度（本版仅单次自动曝光，无预热预览，暗光效果需实测）。
3. 设置间隔 10 秒，亮屏 5 分钟，核对时间和文件数量。界面切后台后保持拍摄。熄屏 30 分钟、2 小时各测一次，核对服务器文件间隔、耗电、温度、是否出现黑图或 Camera2 错误；不得用亮屏测试替代熄屏结论。
4. ColorOS 电池设置允许后台运行、锁定任务后重复；分别测试默认省电和允许后台设置，写明必要配置。被系统限制时记录错误，不宣称通过。Camera2 LEGACY 实现如果无预览拍照失败，需要后续实机调整。
5. 管理端切 front→back→front，各拍 10 张，通过现场不同目标确认实际镜头。切换发生在下一张，不要求中断当前拍照。重复快速切换，确认不会并发打开摄像头或崩溃。
6. enabled=false 后等待当前拍摄完成，至少两倍间隔无新文件；true 恢复。手机点击通知“停止”后不再上传/拍照；远程配置不能重新激活，重启手机也不能自启。
7. 飞行模式 10 分钟后恢复，观察补传；用文件名核对无丢失/重复。联网中停止服务，重新本机启动后补传。模拟服务端丢失上传响应，确认同名重试只保留一份。
8. 错误设备令牌、管理员令牌、TLS 证书分别测试。错误令牌应 401，设备令牌不能修改管理配置。无信任证书时不应降级 HTTP。检查日志和 Git 无令牌。
9. 小容量测试机或专用测试分区模拟低磁盘，确认手机暂停新增、已有文件保留；树莓派低磁盘拒绝上传，手机保留待重试。不要为测试填满日常使用的系统分区。
10. 与系统相机竞争、拔网、杀进程、重启服务器、重启手机分别测试。服务不自动重启是设计行为；本机重新启动恢复队列。手机强停后状态超过90秒离线。
11. 连续运行24小时，记录最大队列、上传延迟、失败率、温度、电量。前后摄各至少熄屏运行2小时；所有相关项通过后才能称该固件已适配。

双摄并发：API 22 不提供 `getConcurrentCameraIds`（API 30）。本版报告未知，所有测试只交替打开；hardwareLevel 不能作为并发支持证据。需要专门的后续诊断版本和现场测试才能确认并发。

后续第二版：先在 R7sm 验证 MediaRecorder + 单摄分段、片段崩溃恢复和音频权限，再评估实时视频编码/传输与树莓派3B负载。不能将本版 JPEG 上传视为录像或实时视频已实现。

## v0.2.0 无服务器本地测试

1. 直接覆盖安装 v0.2.0 APK，勾选“本地测试：无需服务器，不上传照片”。地址和令牌留空；不需要 Wi-Fi、热点或移动网络。
2. 间隔设为10秒，选择后置，点击“同意并启动”。确认常驻通知出现，界面状态显示“已保存本地”；等30秒后点击停止，再进“查看本地测试照片”，确认有可解码的现场照片。
3. 返回启动，运行中选择前置，等待下一张；停止后打开列表，通过文件名 front/back 和照片内容确认镜头。切换不会打断正在进行的一张拍摄。
4. 熄屏5分钟，解锁后停止，查看文件名时间是否持续增长、图片是否正常；再分别做前后摄2小时测试。失败时拍下界面/通知状态。LEGACY 摄像头无预览拍照的兼容性仍以真机为准。
5. 长按列表中的照片可确认删除；本地照片上限约256MiB，低可用空间或达到上限会暂停拍照，不自动删除旧照片。
6. 改模式或间隔需先停止、再启动；本地镜头选择可在运行中切换。取消本地测试才使用原有HTTPS上传模式。本地测试照片独立存储，不会因切回上传模式自动上传。卸载或清数据会删除这些照片。
7. 界面状态为最近事件和时间，不代表进程一定存活；强停/系统杀进程后可能显示旧事件，结合常驻通知、文件时间判断。

## v0.3.0 验收

- 覆盖安装保留旧照片。列表点击多选，全选/取消；长按仍可预览。选择2张确认删除，核对未选照片不受影响；取消确认不删除。
- 选旧格式照片、新照片、MP4，点导出选择“下载”等系统位置。电脑或手机解压 ZIP，检查中文文件名、时间、照片内容及视频可播放，原文件仍存在。取消系统保存不应删除文件；导出时保持页面打开，避免同步删除源文件。系统无文档保存组件时应显示提示。
- 设置拍照间隔10秒、拍照时段30秒、录像5秒、等待10秒；循环至少3轮。拍照阶段约每10秒一张，然后一个约5秒无声MP4，再等待10秒。相机会话初始化/释放耗时会增加实际周期；不保证毫秒级计时。拍照窗口结束时正在拍的一张允许完成，再进入录像。
- 录像中切换镜头，不中断当前片段，下次操作使用新镜头。停止服务时未完成录像丢弃，已完成媒体保留。录像仅本地、无麦克风权限；默认640×480以内的可用尺寸、H.264/15fps。失败会显示状态，不能用生成文件名判定有效录像。
- 熄屏分别执行前/后摄循环各30分钟及2小时。核对视频黑帧、实际时长、画面方向、耗电和温度。LEGACY固件可能拒绝无预览录像，以真机结果为准。
- 点击“前后摄并发拍照/录像诊断”，保持主界面打开最长55秒；拍下结果。程序分别检查两张JPEG的完成、两路视频的有效元数据及录制时间重叠，成功文件保存到本地列表。人工检查两路内容确实分别来自前后摄、视频都可播放；重复3次，并在设备重启后再测。失败可能是驱动限制、相机占用或资源不足，仅记录“本次未通过”。不据单次成功启用正常双路任务，不承诺录像中同时抓拍。
- 新照片文件名按手机系统时区命名；测试前校准手机时间。旧照片仅展示及导出转换，原名和文件未修改。树莓派上传服务升级后，验证中文文件名上传及旧格式补传仍正常。

## v0.3.1 界面/播放回归

用户 R7sm 截图的并发诊断出现 `camera error 2`，即 `ERROR_MAX_CAMERAS_IN_USE`（同时可用摄像头数量上限）。这次并发拍照及并发录像未通过，继续串行使用；不据此推断所有分辨率/固件永远不支持。单路后摄录制有文件生成，但用户反馈旧播放器无法播放，实际片段是否正常仍需复核。

- 列表点击条目直接看图/播放；勾选右侧框仅改变选中数。全选、取消、导出、删除仍有效。长文件名、放大系统字体、窄屏均应自动增高且不被裁切，列表支持滚动。
- 点已有MP4进入独立播放页，检查画面、进度、播放/暂停、拖动、重播、返回列表，锁屏/切后台应释放播放器，返回重新准备。再生成一个新的5秒片段测试。失败应有具体 MediaPlayer 错误码；导出该MP4在电脑或其他播放器复核，以区分录制片段损坏与手机解码/播放问题。修复不承诺能修复已损坏文件。
- 本地保存时不显示HTTPS/令牌；只拍照时隐藏阶段/录像/等待参数。循环显示三个有编号的阶段及实时执行说明；间隔30秒、拍照阶段30秒应说明约1张，间隔10秒则约3张。示例按钮填入10/30/5/10。
- 启动后参数锁定，先停止再修改；本地镜头仍可切换。切回上传模式只提供拍照，并说明连接后服务端配置覆盖间隔；停止、媒体管理与诊断入口保留。

## v0.4.0 R7sm录像修复与串行交替

此前30秒间隔/30秒拍照阶段/5秒录像/10秒等待应产生视频；只看到照片不能断定未进入录像分支。已发现的代码兼容性风险包括 Camera2 LEGACY 无预览单输出、固定15fps、停止封装前关闭会话。因未收到原版阶段错误日志，不能将某一风险当作已证实的真机根因。本版替换为Camera1+持续消费的EGL预览纹理，按设备能力选择尺寸/帧率，先stop封装再释放相机。照片与录像之间留1秒释放缓冲；新增独立保存的最近录像结果和具体失败阶段。

1. 覆盖安装v0.4.0，无需卸载。先选后摄，点击“单独测试当前镜头5秒录像（本地）”，约6–15秒后查看“最近录像”及MP4。前摄重复一次。这个按钮忽略循环计划，只在本地测试一段；运行有常驻通知，结束自动停止。
2. 使用截图参数30/30/5/10，启动并至少等待90秒。预期每轮约1张照片及1段5秒视频。相机初始化和释放导致周期略增，停止过程中未完成片段仍丢弃。失败时“最近录像”保留具体阶段（打开Camera1/配置预览/准备/启动/stop/文件校验），不会被后续拍照状态覆盖；拍下这段文字定位真机问题。
3. 开启“按时间交替”，起始镜头选后摄，每颗镜头60秒。连续运行3分钟以上，通过文件名和现场不同目标验证后→前→后。不在当前录像中途切换，超时切换延后至该操作完成；不补做错过的多次切换。只本地模式支持自动交替，上传模式保持服务端控制。
4. 交替选项关闭时单摄固定/手动切换仍有效。所有双摄并发入口及代码已移除，任何时刻只运行一项拍照/录像任务。
5. 重复亮屏、后台、熄屏5分钟及2小时验证视频可播放、画面非黑、长度合理、状态无错误，并记录温度电量。未完成真机测试前不能称录像已适配成功。
6. 黑色主题、浅色文字，正文约12–13sp、媒体详情11sp、标题14–16sp，保留48dp按钮/选择控件点击区域。验证系统字号放大时可换行和滚动。
